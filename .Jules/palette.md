## 2024-07-24 - Duplicate disabled and aria-disabled states
**Learning:** Found multiple instances where interactive elements (buttons) had both `disabled` and `aria-disabled` set simultaneously. While functionally it works in some browsers, screen readers often read the state redundantly, and it technically contradicts standard HTML5/ARIA best practices which recommend either relying purely on the native `disabled` attribute (which natively handles focus and semantics) OR using `aria-disabled` (if you want the element to remain focusable for explanation purposes).
**Action:** When creating or auditing buttons, ensure we only use the native `disabled` attribute if we want the element removed from tab order. Never combine `disabled={true}` and `aria-disabled={true}`.
