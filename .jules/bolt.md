## 2024-06-25 - Base64 Encoding/Decoding Performance Bottleneck
**Learning:** `Uint8Array.from(binary, (c) => c.charCodeAt(0))` creates a massive O(N) allocation bottleneck for large base64url payloads (like exported subject JSONs). Additionally, using `atob`/`btoa` fallback loops without checking for native `Buffer` when available on the server (e.g. Next.js API routes or SSR) misses out on a ~100x speedup (e.g., 926ms vs 9ms for 5MB). In the browser environment, replacing `Uint8Array.from(...)` with a standard indexed loop `bytes[i] = binary.charCodeAt(i)` brings the client-side decode time down by 10x.
**Action:** When handling `ArrayBuffer` to `Base64` transformations, always use `Buffer.from(data).toString('base64url')` and `Buffer.from(data, 'base64url')` if `Buffer` is available globally, and optimize browser fallbacks to avoid array mapping over huge structures.
