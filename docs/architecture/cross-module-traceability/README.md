# Cross-Module Architectural Traceability Manual

## Overview
This manual maps component interactions across frontend client apps, backend services, and cloud infrastructure targets, creating a clear guide for cross-layer development within the MOLD architecture.

## Component Interactions

### Frontend Client Apps
- **HomeScreen / Nav:** The main entry point, navigating users to either the **GameRunner** or the **AddQuestionsWizard**.
- **GameRunner (Outer & Inner):** The core client loop where the main quiz runs. The `GameRunnerInner` component directly interacts with the `GameEngineProvider`, `StatsProvider`, and the `CheatSheetTerminal`.
- **AddQuestionsWizard:** The Socratic AI Question Generator where users input AI-generated data. It relies on the `DOMPurify` sanitizer before writing to persistence.
- **CheatSheetTerminal:** A drawer component that logs incorrect answers and hints during a game run.

### Client State & Logic Providers
- **GameEngineProvider:** The central React Context managing active quiz state (`GameState`). Driven by `lib/game/game-engine.tsx`.
- **AchievementProvider:** The root context that continuously evaluates player milestones (e.g., via `RunRecord` completion).
- **StatsProvider / ActiveSubjectStore:** Manages player session statistics and the currently active deck of questions.

### Backend Services & External Systems
- **LLM Integration:** The `AddQuestionsWizard` expects text input generated by external LLMs (e.g., Gemini, Claude, GPT).
- **Sanitization & Validation Pipeline:** Raw JSON input flows through a Zod Schema Validation phase (`lib/types/mold-types.ts` structures) and is then scrubbed by `isomorphic-dompurify`.
- **Achievement Evaluator (Async Worker Model):** Processes run completions to trigger unlock notifications and update persistent stores.

### Cloud Infra Targets & Persistence
- **Offline-First Persistence:** The primary datastore currently utilizes **Browser LocalStorage / IndexedDB**. The `ActiveSubjectStore`, `GameEngineProvider`, `AchievementProvider`, and `StatsProvider` all flush data to these browser APIs.

## Interface Properties & Data Pipelines

### Core Data Interfaces
The `lib/types/mold-types.ts` is the central hub for system interfaces:
- `Question` / `MCQ`: Defines the core structure of a quiz item, including options and the correct answer index.
- `GameState`: The active schema for the `GameEngineProvider`, tracking phase, scores, streaks, and current active question index.
- `RunRecord`: The data payload emitted at the end of a session, mapping final scores, elapsed time, and incorrectly answered questions for the `StudyDeck`/`CheatSheetTerminal`.

### The Primary Data Pipeline (Question Ingestion to Run Completion)
1. **Ingestion:** User pastes AI-generated JSON into the `AddQuestionsWizard`.
2. **Validation & Sanitization:** Zod schemas validate structural integrity; `isomorphic-dompurify` prevents XSS. If validation fails, error reports and recovery logs are generated.
3. **Storage:** The clean payload is written to LocalStorage (`active-subject-store`).
4. **Game Loop:** `game-engine.tsx` consumes the store to initialize a `GameState`.
5. **Execution:** User interactions trigger `PlayerAnswer` events. Correct answers increment the streak logic; incorrect answers append data to the `StudyDeck` (Cheat Sheet Logger).
6. **Finalization:** A `RunRecord` is created, stored, and evaluated asynchronously by the `AchievementEval`, concluding with a potential Toast Alert.
